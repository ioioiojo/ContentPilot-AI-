# 0.7.0 上线候选版与验收门槛

这是面向受控团队、单服务器的部署候选版。已提供上线保护和运维入口；尚未连接用户服务器，不等于已经正式上线，也不代表岗位 JD 全部完成。

## 已补齐的上线保护

- APP_ENV=production 强制 PostgreSQL、Secure Cookie、明确真实域名和真实模型配置。Mock 仅用于 development/staging。配置检查不验证密钥实际有效性。
- 每账号文字任务默认最多同时 10 个，滚动 24 小时最多新建 50 个；素材为 5/20。数据库写锁串行化同账号提交，避免并发超额。失败任务也占当天额度，重试仍受原任务总执行预算限制。
- 从环境读取的新文字任务默认最多执行 1 次，避免连接异常后自动重复计费；可设置 JOB_MAX_ATTEMPTS=2/3。旧任务保留创建时的预算。
- SUBMISSIONS_ENABLED=false 暂停新建和手动重试文字/素材任务，重建 web/worker 生效。已排队任务继续执行，若需立即停止调用，停止 worker 并核对供应商已有请求。
- /health 检查数据库；/ready 还检查 worker 最近 90 秒内的数据库心跳。web 容器启动仍使用 /health，避免 worker 等 web、web 又等 worker 的死锁。worker 卡死、失联和数据库失败由外部监控发现。
- /api/admin/runtime 仅管理员可读，返回版本、环境、队列数量、执行进程状态及限额，不包含成员内容或密钥。
- Compose 限制日志体积。部署/恢复互斥，升级停写后先备份再迁移；恢复前再备份当前数据库。失败保持应用停止供检查。

任务限额不是人民币预算：单次模型 Token、单张图片/视频价格及供应商重计费不受这些数量限额保证。供应商侧还应设置消费上限/余额告警；真实单任务成本和质量需用实际配置验收。

## 服务器操作

1. 上传 0.7.0 发布包到专用项目目录，保留现有网站配置。运行 prepare_server_env.sh。
2. 编辑 .env：真实 ALLOWED_HOSTS、模型密钥、OPENAI_BASE_URL=https://flux-code.cc、OPENAI_MODEL=gpt-5.5；密钥仅存服务器，不发送到聊天。保留 APP_ENV=production、CONTENTPILOT_PROVIDER=compatible。
3. 首次执行 sh scripts/deploy.sh first；已有部署使用 upgrade。脚本构建、检查配置、启动数据库、初始化、等待 web/worker 就绪。保留旧包/镜像，升级失败不能仅换回旧代码；回滚用 restore.sh 的 --keep-stopped 恢复升级前备份，再切换匹配的旧代码和镜像。
4. 按 README 接入子域名 HTTPS，创建管理员，并验证登录、用户隔离、真实文字任务、人工修改/通过/拒绝、导出和真实效果录入。/ready 通过不代表模型接口或外部服务可用。
5. 执行备份，复制到另一台受控存储；用独立测试数据库做恢复演练，确认账号和历史内容可恢复。

本机没有 Docker，Linux 镜像、PostgreSQL 和恢复流程尚未在本机运行。CI 已增加真实 PostgreSQL 并发/迁移测试、Compose 启动及队列/审核/导出/备份恢复演练；上传仓库并得到绿色结果后，仍须完成目标服务器验收。

## 每日备份和监控

以下是部署完成后供管理员安装的 crontab 示例，替换 /opt/contentpilot 为实际绝对项目目录，先创建受限 logs 目录。不要把密钥写进 crontab：

```cron
15 2 * * * cd /opt/contentpilot && sh scripts/backup.sh >> logs/backup.log 2>&1
*/5 * * * * cd /opt/contentpilot && sh scripts/monitor.sh >> logs/monitor.log 2>&1
```

monitor.sh 检查 /ready 和过去 26 小时是否生成备份，失败返回非零。日志本身不等于告警：将该退出状态接入已有监控/告警服务，并验证能收到故障告警。备份目录需监控磁盘、制定保留策略和异地复制；脚本不自动删除旧备份。脚本须在 Docker 权限的运维账号下运行，监控日志也需轮转。
