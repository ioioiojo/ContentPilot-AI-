# 小红书关键词搜索与 AI 二创（0.6.1）

0.7.0 可以直接由管理员在「服务配置」→「小红书搜索与实时热点」填写 TikHub 密钥，保存即对下次请求生效；命令行方法仍适用于环境配置。页面配置优先于环境变量，因此已有页面配置时请在页面更新。新增功能见 [FEATURES.md](FEATURES.md)。

## 当前可以使用的流程

登录 →「参考帖二创」→ 输入关键词 →「去小红书搜索」→ 在小红书查看帖子 →「手动录入参考帖」保存标题、正文、作者和链接 → 最多选择 5 条 →「用所选参考帖创建二创」→ 选择商品事实、目标用户和二创要求 → 后台生成 → 人工审核 → 导出。

配置 TikHub 后可改为：输入关键词 → 选择数量、排序和笔记类型 →「搜索并导入」→ 读取正文并保存参考库 → 选择参考帖 → AI 二创及人工审核。当前用户没有 TikHub 密钥，自动搜索尚未真实接通；不能把模拟测试作为真实搜索结果。

也可以在普通「新建任务」里选择最近录入的参考帖，不选时沿用原有商品资料生成。参考库支持关键词筛选、分页及删除；每账号最多保存 1000 条，彼此隔离。录入链接不会自动读取正文，手动来源不冒充搜索服务结果；本地示例话题不等于真实小红书帖子。

AI 将参考帖正文作为不可信资料，只归纳主题、结构与读者需求，重新组织表达。商品功效、规格、价格等仍以商品资料为准，不套用原作者的评价或体验。任务、发布来源和导出保留当时的参考快照及二创要求；删除参考库记录不改变已提交任务。

审核对标题完全重复（规范化后至少 12 个字符）和正文连续 32 个文字/数字重复进行提示，忽略标点与空白后仍能检测，命中时禁止人工直接批准，编辑后可重新审核。这是辅助规则，不能证明完全原创、事实正确或拥有素材使用权，短句、语义换写等仍需人工核对。

## 小红书 API 的范围

小红书有官方开放平台和广告平台，但本项目尚未核实到面向个人账号的通用“关键词搜索普通笔记正文”官方权限。电商商品、订单、广告接口不能直接当作普通笔记搜索接口。因此当前不内置猜测的私有接口、登录 Cookie 抓取或反爬绕过逻辑。

本版实现 TikHub 第三方数据服务适配，接口目标是小红书。它不是小红书官方 API；商业服务可用不等于已取得小红书官方授权，使用范围需要根据服务条款核实。

## TikHub 开通与配置

1. 访问 [TikHub](https://www.tikhub.io/) 注册账号，在服务控制台取得 API 密钥，确认小红书 App V2 搜索及笔记详情接口可用、计费规则和额度。小红书个人账号登录不能替代此密钥。
2. 本地在项目目录运行下面的命令，按提示隐藏输入密钥。不要把密钥发到聊天里。命令只更新现有 .env 的搜索配置，保留原文字模型设置，不请求付费接口。

```powershell
.\.venv\Scripts\python.exe -m contentpilot_agent.manage configure-tikhub
```

服务器可直接在现有 .env 添加或修改以下两项（占位符须替换为真实密钥）：

```dotenv
CONTENTPILOT_SEARCH_XIAOHONGSHU_PROVIDER=tikhub
TIKHUB_API_KEY=你的真实密钥
```

3. 本地重启 web/worker（见根目录 README）；Docker 服务器在项目目录执行 `docker compose up -d --build --force-recreate web worker`，让新环境变量生效。
4. 登录 →「参考帖二创」→ 关键词建议「通勤咖啡」，首次选择 1 条 →「搜索并导入」。核对返回的真实标题、作者、正文及原帖链接，再选帖创建二创。界面显示“已配置”只表示填写了密钥，不代表接口已通过验收。

公开文档核对日期为 2026-10-10：

- 搜索：GET `https://api.tikhub.io/api/v1/xiaohongshu/app_v2/search_notes`，Bearer 密钥，keyword、page=1、sort_type、note_type、ai_mode=0。见 [搜索文档](https://docs.tikhub.io/420136398e0)。
- 正文：GET `https://api.tikhub.io/api/v1/xiaohongshu/app_v2/get_image_note_detail`，note_id。文档说明可返回图文和视频笔记的文字详情；此功能不下载视频。见 [详情文档](https://docs.tikhub.io/420136391e0)。
- 本次公开文档没有实际嵌套 data 样例。适配器对 notes/items/note_list 等结构作防御解析并以模拟数据验证；取得密钥后须核对实际返回格式，必要时按真实响应调整。未知结构会报错，不当作零结果。

每次读取第一页最多 5 条；默认 3 条，可选择 1/3/5 条。最多发起 1 次搜索 + N 次正文读取，详情最多 3 路并发；不是按笔记数量直接确定货币费用。失败或正文不可用的请求也可能被服务计费，不自动重试。全部正文校验通过才整批导入，不用搜索摘要冒充全文。

每次请求设置最多 7 秒 HTTP 超时，共享 22 秒截止时间并在请求前和读取响应时检查；该检查不等于整个操作硬性 22 秒终止。单响应解压后最多 2 MB，不跟随重定向。密钥错误、余额不足、限流、正文不可用和不支持的格式均显示固定提示，不展示上游原始响应。

provider=auto 时优先选择已配置 URL+TOKEN 的旧网关，否则选择 TikHub；指定 tikhub 不使用网关令牌或文字模型密钥。每账号每分钟 1 次、滚动 24 小时 30 次；失败计入次数，但缺少密钥或超出数量限制在请求前拒绝。停用 TikHub 可清空 TIKHUB_API_KEY 并重启 web；auto 模式还应确认旧网关未配置。

## 搜索网关协议

已经预留 HTTPS 搜索网关，可在服务器 .env 填写：

```dotenv
CONTENTPILOT_SEARCH_XIAOHONGSHU_URL=https://你的已授权服务/notes/search
CONTENTPILOT_SEARCH_XIAOHONGSHU_TOKEN=由服务商提供的令牌
CONTENTPILOT_SEARCH_XIAOHONGSHU_PROVIDER=gateway
```

配置后重建 web/worker；凭据只存服务器，不出现在页面或导出里。网关协议是本项目的适配协议，不能直接假定任何第三方接口与之兼容；不兼容时需要编写对应转换服务。

请求为 POST，Authorization: Bearer TOKEN，Idempotency-Key 为此次请求 ID：

```json
{"platform":"xiaohongshu","keyword":"通勤咖啡","limit":5}
```

返回 HTTP 200 JSON，posts 数组最多 limit 条，允许空数组：

```json
{"posts":[{"title":"笔记标题","body":"实际可用的笔记正文","url":"https://www.xiaohongshu.com/explore/笔记ID","author":"作者"}]}
```

title 最长 200，body 最长 6000，author 最长 120，url 最长 2000 字符，字符串不能以空内容代替必填字段。url 仅接受小红书笔记 HTTPS 路径或 xhslink 分享链接；应用不会主动访问此链接。请求关键词由本系统记录，忽略服务返回的 keyword；额外字段需在适配器中去掉，以免整个结果校验失败。

默认 15 秒 HTTP 超时，不跟随重定向；解压后的响应最多 512 KB。结果整批校验，错误不导入半批数据、不生成示例结果、不自动重试。一次结果内同主机和笔记路径去重。配置仅代表已填写参数，正式可用仍需要真实调用验收。

每账号每分钟最多 1 次、滚动 24 小时最多 30 次搜索，失败请求也计入额度；检查与记录在同账号数据库锁下执行。现有任务暂停开关只暂停 AI 任务，不暂停搜索；如要停用搜索服务，清空两项配置并重建 web。
