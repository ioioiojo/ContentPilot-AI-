# 0.7.0 功能与 API 管理

## 页面入口

管理员登录后，左侧「服务配置」按 AI、搜索与热点、发布、运营数据分类管理。填写地址/模型/密钥，勾选启用并保存。密钥加密保存，不回显；空白保留已有密钥，清除须另勾选。页面配置覆盖环境同名设置，停用后不回退到该服务的旧密钥；TikHub 与搜索网关只启用一个。保存后下次请求/任务使用新配置，无须重启。运行中的任务保持配置快照，避免接口和密钥错配。

仅管理员可管理全局服务。配置更改与连接测试记录操作者和时间，不保存密钥到日志/审计。后台读取真实凭据，页面和导出不返回密钥。服务器的数据库、域名、HTTPS、任务限额和 production 模式仍由服务器配置控制。

连接测试的范围：文字/图片 GET 地址/models，确认模型存在，不生成素材；视频/发布/运营网关 GET 地址/health，须返回 `{"status":"ok"}`，不执行发布或采集。TikHub 测试调用真实搜索和最多一次详情，可能计费；搜索网关/热点测试也可能使用额度。测试通过不替代真实业务验收；不支持探测端点的供应商须调整适配。仅填密钥不能使任意供应商自动符合协议。

## 知识库与实时热点

「知识库与热点」保存资料标题、正文和来源，每账号最多 500 份；可检索、查看和删除，API 也支持修改。当前是本地关键词相关性检索，不依赖向量 API。新任务默认按商品名与目标用户检索最多 5 条，保存不可变摘录和来源；可取消「检索我的知识库」。资料删除不改变旧任务。资料和外部话题均作为不可信数据处理，不执行其中指令，不覆盖商品事实。

真实热点须在「服务配置」填写热点网关，POST 协议：

```json
{"keyword":"咖啡","platforms":["xiaohongshu"],"limit":10}
```

响应示例（仅展示协议，不是实际热点，时间需替换）：

```json
{"topics":[{"title":"真实话题标题","url":"https://来源链接","platform":"xiaohongshu","captured_at":1791580000}]}
```

话题须有真实 HTTPS 来源和最近 24 小时时间，最多 10 条；页面搜索后，新任务勾选引用刚获取的真实热点。服务器保留所属账号的批次，不接受伪造或别人的批次，超过 24 小时须重取。获取热点与参考帖搜索共享每分钟 1 次/滚动 24 小时 30 次预算。未使用真实热点时，选题仍明确标为本地示例。

## 独立审稿与断点续跑

管理员在「成员管理」启用成员审稿资格。任务所有者在待审核/驳回的详情选择审稿人并保存；审稿人在「审核中心」打开分配任务。分配后通过/驳回由审稿人执行，所有者仍能编辑；所有者可在待审核/驳回时撤销或更换分配，操作留审计。分配更新任务版本，旧页面审核会冲突。停用账号或撤销审稿资格后失去分配任务权限。审稿人不能读取其他任务，也不能替所有者发布、导出或管理商品。

生成每完成选题、生成、审核、修改一步，就在租约校验下持久化断点。中断后的重试从下一个未完成节点继续，保留已完成选题/草稿、模型统计和版本历史。失败任务有断点时，所有者可以「从断点继续生成」，显式增加一次执行预算，总次数最多 3；继续受并发限额和暂停开关限制。尚未完成的网络调用仍可能已计费，断点机制不保证供应商请求恰好执行一次。旧版本没有断点的失败任务仍需按旧重试规则或新建任务。

## 运营数据自动采集

已发布记录中点击「自动采集」：可立即入队，也可设置至少 60 分钟的间隔。worker 调度并执行，跨进程原子领取、租约隔离、最长 90 秒且不超过任务总超时；失败不自动重发当前采集请求，下个计划时刻是新的数据测量。每账号滚动 24 小时最多 30 次，同时最多 5 个；停用账号不继续计划，SUBMISSIONS_ENABLED=false 暂停计划入队和人工提交。采集历史显示状态、实际数据和错误。

小红书已配置 TikHub 搜索密钥且没有专用指标网关时，可读取完整 24 位笔记 ID 链接的公开点赞、评论、收藏、分享。短链接需先换成完整笔记链接。缺少或无法解析的计数不会编造；此适配的嵌套结构只有模拟测试，需真实密钥首次验收。不能通过公开互动数取得私有后台曝光、点击、成交、营收等指标。

完整数据通过已授权的运营网关，POST `CONTENTPILOT_METRICS_平台_URL`，Bearer TOKEN，Idempotency-Key 为采集任务 ID：

```json
{"publication_id":"本地发布ID","platform":"xiaohongshu","url":"https://实际发布链接"}
```

响应须回传相同 publication_id。以下仅展示协议：

```json
{"publication_id":"本地发布ID","metrics":{"captured_at":1791580000,"evidence":"平台后台报表编号","impressions":1000,"clicks":100,"conversions":10,"revenue":790,"cost":100,"likes":30,"comments":5,"collects":8,"shares":2}}
```

未提供的字段允许省略或 null；至少有一个实际指标、时间和依据。累计成交≤点击≤曝光（提供时验证），不接受未来时间、负值或非有限数。仅全部曝光/点击/成交/营收/成本存在时写入现有效果快照并进入 CTR/转化率/ROI；部分互动指标单独显示并可作为下一轮选题参考，不推算缺失业务数据。统计使用最新累计快照，不相加。供应商须自行获取所选平台的权限与真实数据；本项目不冒充官方个人账号后台接口。

## 图片、视频和发布

图片和视频的地址/模型/密钥均可从管理页面配置，后台队列、文件校验与下载沿用原实现。接口要求见 [INTEGRATIONS.md](INTEGRATIONS.md)。未取得供应商和额度时，这些服务保持未接通；分镜只生成文字 JSON。

当前已审核版本的图片/视频完成并经人工核对后，发布弹窗可勾选所选文案的素材。服务器再次核对账号、任务、内容、版本、完成状态和总体大小，旧版本或别人的素材拒绝。网关请求在原协议上增加 `assets` 数组，各项为 id、mime、b64_json；不选素材时保持旧协议。发布 source 只保留素材元数据，不重复存 base64。网关需实现平台授权、素材上传和发布，只有 published+有效链接才确认；重复请求不重发，结果不明须人工核对。

## 加密密钥、备份与升级

schema v5 仅新增服务配置/审计、知识文档、话题批次、审稿资格/分配、工作流断点、采集订阅/任务表，不修改旧列。升级前停止 web/worker 并备份，保留 .env 和账号。

首次保存配置时，本地自动在 data/service-config.key 生成 Fernet 密钥；Docker 使用 web/worker 共享的 service_keys 命名卷（/app/secure）。可通过 CONTENTPILOT_CONFIG_KEY 提供固定 Fernet 密钥，优先于文件。不要删除密钥或使用 `docker compose down -v` 清空卷。

SQLite backup-local 在有密钥时另写 `<备份>.key`；服务器 backup.sh 导出已验证的密钥为 `<备份>.dump.key`，restore.sh 在恢复数据库后还原配对密钥并检查能解密，再启动。环境密钥与备份不同时会拒绝启动恢复流程，须由服务器管理员配置匹配值。数据库和 key 都是敏感备份，权限限制和异地受控存储缺一不可；密钥不进入源码发布包。Docker 构建与 PostgreSQL 恢复仍需在目标服务器实测。
